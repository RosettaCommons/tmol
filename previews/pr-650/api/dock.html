Docking#

Ligand docking: a genetic-algorithm search over a ligand’s placement, its torsions, and optionally pocket sidechains, scored on a precomputed receptor grid. tmol.dock.run_docking() is the entry point; see Ligand docking for the workflow.

Docking of a small molecule into a rigid or flexible-sidechain receptor.

Dock one ligand of a protein-ligand complex pose_stack (a single-pose PoseStack holding the receptor and the ligand in any placement):

from tmol.dock import GridBackend, GASchedule, run_docking

# The GA runs on the pose's device; build the pose where you want to search.
backend = GridBackend.from_pose_stack(pose_stack, "LG1", param_db)
result = run_docking(pose_stack, backend, schedule=GASchedule())
result.best_pose_stack, result.best_energies

"LG1" is the ligand’s residue name; a block index, or a boolean mask over the pose’s atoms selecting exactly the ligand’s atoms, work too. To dock many ligands, build one complex and one backend per ligand; to let pocket sidechains move, pass flexible_residues=select_pocket_residues(pose_stack, "LG1").

The docked ligand’s coordinates come back in its block type’s atom order; a ligand prepared from a MOL2/SDF names its atoms by element plus the input file’s 1-based atom index (Cl8).

class tmol.dock.ContinuousBackend(ligand_block: int, param_db: ParameterDatabase | None = None, *, kin_dtype: dtype | None = None, value_only_line_search: bool = False)[source]#

Bases: ScoringBackend

Full continuous beta2016 scoring and kinematic minimization.

param_db should be the ligand-extended parameter database returned by ligand preparation. If it is omitted, tmol’s memoized default beta2016 score function is used. A score function is cached per device, while the whole-pose scoring module is rendered for each input PoseStack.

Parameters:

  • ligand_block – Block index of the ligand in the complex to be docked.

  • param_db – Optional ligand-extended scoring parameter database.

  • kin_dtype – Internal-coordinate dtype for minimization. By default the input coordinate dtype is used.

  • value_only_line_search – Evaluate Armijo trials without gradients and refresh the gradient at the accepted point (default: False).

class tmol.dock.RefineProtocol(steps: tuple[dict[str, float], ...], cycles: int = 1, max_iter: int = 50, top_k: int = 20, space: str = 'cartesian', opt_h: bool = False, backbone_neighbors: int = 0, sidechains: str | tuple[int, ...] = 'backend', repack: bool = False)[source]#

Bases: object

Exact-stage refinement, in the vocabulary of Rosetta’s relax scripts.

steps are fast_relax schedule entries: each repacks the movable sidechains at fa_rep_pack_frac and minimizes at fa_rep_min_frac, one entry per Rosetta ramp_repack_min line. cycles is its repeat, and the best-scoring state across cycles is kept.

sidechains chooses what moves: "backend" takes the set the backend declared, () holds the receptor rigid, and an explicit sequence of block indices overrides both – the relax stage need not use the same freedom the search did.

repack: bool = False#

Rebuild the movable sidechains from the rotamer library at each step; off leaves them at the conformation the search produced.

ramp() → tuple[tuple[float, float, int], ...][source]#

(fa_rep multiplier, tolerance, iterations) per step.

Bases: object

Single-stage VSX schedule for the continuous backend.

sidechain_sampling: Literal['jitter', 'rotamer', 'packer', 'minimize'] = 'rotamer'#

How flexible sidechains are searched. jitter perturbs their chis with the ligand’s operator; rotamer mutates them to whole Dunbrack rotamers; packer leaves them to an annealed rotamer search before each minimization, as Rosetta does; minimize never samples them genetically, so they adapt only through the continuous minimizer and the final refinement’s repack.

pack_steps: int = 50#

Annealing passes per ramp step, for packer.

pack_contact_cutoff: float | None = None#

Contact distance biasing which residue a packing pass proposes; None draws residues uniformly.

ramp: tuple[float, ...] = (0.1, 1.0)#

Repulsive-weight ramp; each entry packs at that weight, then minimizes.

class tmol.dock.GridBackend(grids: GridSet, ligand_block: int, ligand_atom_types: tuple[str, ...], ligand_charges: Tensor, param_db: ParameterDatabase | None = None, *, kin_dtype: dtype | None = None, live_hbond: LiveHBondData | None = None, live_ligand_intra: LiveLigandIntraData | None = None, live_lk_ball: LiveLKBallData | None = None, lk_ball_grid: bool = False, score_function: ScoreFunction | None = None, sidechain_blocks: tuple[int, ...] = (), context_blocks: tuple[int, ...] = (), grid_atom_indices: Tensor | None = None, movable_n_atoms: int | None = None, cuda_graph: bool = True)[source]#

Bases: ScoringBackend

Rigid-receptor grid plus live hbond, intra, and LK-ball scoring.

One GridSet is retained by the backend and shared by every pose. Device/dtype copies are cached once and do not scale with population size. The grid contains fa_atr, fa_rep, fa_sol, and fa_elec, plus three weighted LK-ball grid families when lk_ball_grid is true. One receptor hbond structure, ligand-intra topology, and ligand-water topology are shared by every ligand pose; lk_ball_grid=False retains the exact live LK-ball implementation. Ligand-intra search weights match Rosetta GridScorer’s softened oneb_wtd_ objective.

Minimization is a batched L-BFGS whose line search evaluates n_trials step sizes of every pose at once; with cuda_graph each iteration is one CUDA-graph replay.

search_view(pose_stack: PoseStack) → tuple[PoseStack, GridBackend, tuple[int, ...]][source]#

Compact ligand(+flexible sidechain) pose the GA searches over.

for_ligand_block(ligand_block: int) → GridBackend[source]#

Return a lightweight view targeting another ligand block index.

Grid construction fixes the ligand chemistry, not its block position in a scoring PoseStack. The ligand-only docking representation places the same block type at index zero. A shallow copy preserves the single grid and its device/dtype caches while allowing that representation to use the ordinary backend contract, whose score method has no block argument.

Receptor grids of the box around ligand, to share across ligands.

The grids depend on the receptor, the box and the probe atom types, not on the ligand: build them once for the union of the ligands’ atom types and pass them to every from_pose_stack() of a screen (atom_types defaults to the ligand’s own types).

classmethod from_pose_stack(reference_pose_stack: PoseStack, ligand, param_db: ParameterDatabase, *, flexible_residues: Sequence[int] | None = None, grids: GridSet | None = None, grid_device: str | device | None = None, voxel_spacing: float = 0.25, bbox_padding: float = 4.0, kin_dtype: dtype | None = None, lk_ball_grid: bool = True, include_ligand_intra: bool = True, cuda_graph: bool = True, ligand_intra_weight_profile: str = 'search', score_function: ScoreFunction | None = None) → GridBackend[source]#

Build the receptor grid and live terms for one ligand of a complex.

Parameters:

  • reference_pose_stack – One pose holding the receptor and the ligand (in any placement; the search starts from random poses).

  • ligand – The ligand: residue name ("ATP"), block index, or a boolean atom mask selecting exactly its atoms.

  • param_db – Scoring database including the ligand’s parameters.

  • flexible_residues – Receptor residues (block indices, e.g. from select_pocket_residues()) whose sidechains move.

  • grids – Receptor grids to reuse instead of building them, e.g. one set shared by every ligand of a screen (see pocket_grids()); must cover this ligand’s atom types and have been built for the same flexible residues.

  • grid_device – Device the grids are built on (default: CUDA if available, else CPU).

lk_ball_grid=True selects Rosetta’s weighted gridded approximation; False retains the exact live LK-ball path. Ligand-intra scoring is enabled by default with Rosetta’s softened search profile. cuda_graph captures each optimizer iteration as one CUDA graph (ignored on CPU).

rep_scale(scale: float)[source]#

Scale fa_rep for the duration of the block, as Rosetta packing does.

Rosetta packs each ramp step at a softened repulsive weight and then minimizes at the full one (GridScorer::optimize).

score(pose_stack: PoseStack) → Tensor[source]#

Return one grid GA objective energy per pose.

This is the grid ligand-receptor terms (grid LJ/LK/elec + live hbond + live LK-ball) plus, by default, the live ligand-intramolecular energy – NOT a pure interface energy. Disable the intra contribution by building the backend with include_ligand_intra=False.

minimize(pose_stack: PoseStack, docking_dofs: LigandDockingDOFs, *, maxiter: int | None = None, initial_raw_dofs: Tensor | None = None) → MinimizationResult[source]#

Minimize with direct analytic grid and kinematic derivatives.

The optimizer holds only freed docking DOFs and a bounded L-BFGS history. Each closure uses the valid full-pose KinForest ordering, short-lived compiled kinematic/grid-gradient buffers, and explicitly assigned gradients. Ligand-intra kernels use a local autograd graph internally and return detached values; no graph reaches the optimizer. Selected receptor-sidechain DOFs receive grid, live-interface, and whole-movable gradients; all other receptor DOFs remain fixed.

class tmol.dock.RandomPlacement(pocket_padding_angstrom: float = 2.0)[source]#

Bases: object

Ranges for an unbiased initial ligand population.

The ligand heavy-atom centroid is placed uniformly inside the supplied pocket axis-aligned bounding box. When no box is supplied, the reference ligand-heavy-atom box is expanded by pocket_padding_angstrom on every side. Orientations are uniform on SO(3), and each logical torsion is uniform on (-pi, pi].

tmol.dock.run_docking(pose_stack: PoseStack, backend: ScoringBackend, *, schedule: GASchedule = GASchedule(generations=10, npool=800, rmsdthreshold=2.0, pmut=0.2, maxiter=50, initial_perturbation=DockingPerturbation(translation_angstrom=0.25, rotation_radians=0.08726646259971647, torsion_radians=0.17453292519943295), sidechain_sampling='rotamer', pack_steps=50, pack_contact_cutoff=None, ramp=(0.1, 1.0)), seed: int = 0, initialization: Literal['random', 'jitter', 'conformer', 'aligner'] = 'random', pocket_bounds: torch.Tensor | None = None, random_placement: RandomPlacement = RandomPlacement(pocket_padding_angstrom=2.0), ligand_mol2: str | Path | None = None, n_conformers: int = 200, seed_fraction: float = 0.5, energy_window: float = 20.0, cluster_rmsd: float = 0.5, ligand_aligner: LigandAligner = LigandAligner(n_candidates=4000, seed_fraction=0.5, cluster_rmsd=2.0, diversity_pool_size=512, score_batch_size=4096), finalize: bool | 'RefineProtocol' = False, top_k: int | None = None) → DockingResult[source]#

Dock the backend’s ligand into the complex pose_stack.

pose_stack is the single-pose complex the backend was built from, with the ligand in any placement. The backend chooses the ligand and which receptor sidechains are flexible; a genetic algorithm (schedule) then searches ligand pose, torsions and flexible chis.

initialization selects the starting population: "random" places the ligand randomly (inside pocket_bounds if given), "jitter" perturbs the input pose (refinement), "conformer" seeds torsions from a conformer library of ligand_mol2, "aligner" uses ligand_aligner.

finalize=True uses the refinement protocol matching the backend’s mode (FLEX_REFINE when it declares flexible sidechains, else RIGID_REFINE); pass a RefineProtocol to override it, and top_k to override that protocol’s candidate count.

Without finalize the result holds the grid-ranked pool. With finalize set the top candidates are promoted to full complexes, exact-refined, and ranked by exact complex energy. best_pose_stack follows that ranking; the returned energies are the corresponding dG estimates in the same order. best_genes / ranked_genes stay the grid-GA genes (Cartesian refinement changes bond lengths that torsion genes cannot represent). The grid-GA output is always available as ga_result.

tmol.dock.select_pocket_residues(pose_stack: PoseStack, ligand, cutoff: float = 4.0) → Tensor[source]#

Return sorted polymer residues (block indices) contacting ligand heavy atoms.

A block is selected when any of its heavy atoms is within cutoff of a ligand heavy atom in any pose. Non-polymer blocks, including cofactors and solvent, are excluded. Polymer residues carrying a non-polymer covalent connection (e.g. a disulfide-bonded cysteine) are also excluded, because flexible-sidechain kinematics cannot preserve that bond; passing such a residue explicitly is rejected downstream by validated_sidechain_blocks. Chi-less residues (e.g. ALA, GLY) are excluded as well: they have nothing to move, and so are residues whose sidechain closes a ring onto the backbone (e.g. PRO), whose chis no controller can rotate independently. The returned set is directly usable as flexible sidechain_blocks.
